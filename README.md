# SAE Steering

Исследовательский проект по интерпретируемому управлению поведением языковых моделей с помощью Sparse Autoencoders (SAE).

## О проекте

Большие языковые модели кодируют различные свойства текста во внутренних активациях. Sparse Autoencoders позволяют представить плотные активации модели в виде набора разреженных признаков.

В проекте исследуется, можно ли использовать такие признаки не только для интерпретации модели, но и для управления её поведением во время генерации без изменения весов LLM.

## Цель

Проверить, позволяют ли SAE-признаки воспроизводимо и избирательно изменять поведение языковой модели.

Планируется исследовать:

- отказ от ответа и другие safety-свойства;
- семантические концепты;
- тональность и эмоциональную окраску;
- стиль генерации;
- язык ответа;
- другие интерпретируемые свойства поведения модели.

## Основные задачи

- Научиться извлекать внутренние активации LLM.
- Подключить публичные Sparse Autoencoders.
- Сформировать контрастные наборы промптов для выбранных свойств.
- Найти SAE-признаки, связанные с целевым поведением.
- Сравнить методы выбора признаков.
- Реализовать вмешательство в residual stream во время генерации.
- Провести эксперименты по слоям, признакам и силе вмешательства.
- Оценить целевой эффект, побочные изменения и качество генерации.
- Сравнить SAE steering с prompting и обычными steering-векторами.
- Проверить переносимость результатов между несколькими семействами моделей.

## Исследовательские вопросы

1. Какие SAE-признаки статистически связаны с выбранным поведением?
2. Действительно ли вмешательство в эти признаки причинно изменяет ответ модели?
3. На каких слоях управление работает лучше всего?
4. Как сила вмешательства связана с величиной эффекта и потерей качества?
5. Насколько избирательно меняется целевое свойство?
6. Переносятся ли результаты между промптами, датасетами и моделями?
7. В каких условиях SAE steering лучше или хуже простых baseline-методов?

## План работы

### Этап 1. Подготовка

- Изучить основные работы по SAE и activation steering.
- Выбрать небольшую LLM и совместимый публичный SAE.
- Настроить воспроизводимое окружение.
- Реализовать загрузку модели, SAE и извлечение активаций.
- Воспроизвести простой пример вмешательства в один признак.

### Этап 2. Данные и EDA

- Выбрать одно основное целевое свойство.
- Подготовить положительные, отрицательные и нейтральные промпты.
- Разделить данные на train, validation и test.
- Исследовать распределения SAE-активаций по слоям.
- Найти признаки-кандидаты несколькими методами.

### Этап 3. Первые эксперименты

- Реализовать усиление, подавление и абляцию SAE-признаков.
- Провести перебор слоёв, признаков и силы вмешательства.
- Построить зависимости между силой steering и изменением поведения.
- Сравнить результаты с исходной моделью, prompting и DiffMean/CAA.
- Проверить случайные признаки как placebo baseline.

### Этап 4. Расширенное исследование

- Проверить несколько типов поведения.
- Повторить ключевые эксперименты на другой модели.
- Исследовать перенос признаков между датасетами и моделями.
- Оценить побочные изменения, устойчивость и сохранение качества ответа.
- Провести статистический анализ и оформить итоговые результаты.

### Этап 5. ML-сервис

- Добавить API для обычной и управляемой генерации.
- Реализовать выбор модели, слоя, SAE-признака и силы вмешательства.
- Возвращать исходный и изменённый ответы вместе с метриками.
- Добавить журналирование параметров эксперимента и версий моделей.

## Базовые методы сравнения

- Исходная модель без вмешательства.
- Управление через инструкцию в промпте.
- Difference-in-Means / CAA steering vector.
- Случайный SAE-признак.
- SAE-признак с максимальной разницей средних активаций.
- Признаки, выбранные линейным классификатором.
- Признаки, выбранные по фактическому причинному эффекту.

## Метрики

- Изменение целевого свойства.
- Сохранение смысла исходного ответа.
- Качество и связность генерации.
- Perplexity или log-probability.
- Частота повторов и вырожденных ответов.
- Побочные изменения других свойств.
- Устойчивость по промптам и случайным seed.
- Обобщение на тестовые данные и другие модели.

## Воспроизводимость

Для каждого эксперимента необходимо сохранять:

- конфигурацию запуска;
- название и ревизию модели;
- название и ревизию SAE;
- датасет и его версию;
- слой и идентификаторы признаков;
- способ и силу вмешательства;
- параметры генерации и seed;
- итоговые метрики.

Веса моделей, SAE и большие датасеты не следует добавлять непосредственно в Git. Вместо этого можно хранить ссылки, версии, контрольные суммы и скрипты загрузки.

## Ожидаемый результат

Результатом проекта должен стать воспроизводимый экспериментальный pipeline, позволяющий:

1. находить SAE-признаки, связанные с поведением LLM;
2. вмешиваться в выбранные признаки во время инференса;
3. измерять целевой и побочные эффекты;
4. сравнивать SAE steering с сильными baseline-методами;
5. проверять устойчивость выводов на нескольких моделях.
